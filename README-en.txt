==============================================================================
AIRFLOW SELF-TRAINING BY EXAMPLE - DOCKER VERSION (v2.1)
==============================================================================

This project allows you to deploy a complete Data stack (Airflow 2.6, Postgres 13,
FastAPI and Flask) in isolation on Ubuntu 24.04.

-----------------------------------------------------------------------
1. ARCHITECTURE AND STRUCTURE OF THE PROJECT
-----------------------------------------------------------------------

airflow-study/
├── dags/                <-- Tes scripts DAGs Airflow (.py)
├── logs/ <-- Execution logs (managed by Docker)
├── plugins/ <-- Possible Airflow extensions
├── config/ <-- Configuration files (airflow.cfg)
├── docker-compose.yaml <-- Orchestration of the 5 services
├── Dockerfile <-- Unified image (Airflow + Flask + FastAPI)
├── Makefile <-- Simplified stack management
├── mini_serv.py <-- Flask Server (Reporting /var/tmp/ventes.csv)
├── mini_serv2.py <-- FastAPI Server (ORM / SQL Interface)
├── sales_class.py <-- Data Models (SQLAlchemy)
├── sales.csv <-- Raw data source (standardized _)
└── .env <-- User UID variable (self-managed)

-----------------------------------------------------------------------
2. COMMISSIONING PROCEDURE (AFTER PURGING)
-----------------------------------------------------------------------

STEP 1: Complete initialization
Prepare image, initialize database, create user
admin and automatically sets system permissions.
$ make airflow-init
(Note: Your sudo password will be requested to fix permissions)

STEP 2: Launching the stack
Starts all background services and synchronizes data.
$ make airflow-run

STEP 3: Verification
Verify that all 5 containers are active.
$ docker ps

-----------------------------------------------------------------------
3. ACCESS TO SERVICES AND APIs
-----------------------------------------------------------------------

- Interface Airflow     : http://localhost:8080 (admin / admin)
- Flask API (Reporting): http://localhost:8181/magasin/<STORE_NAME>
-> Example: http://localhost:8181/magasin/Magasin_A
- API FastAPI (Backend) : http://localhost:8000/docs (Documentation Swagger)
- Base Postgres         : localhost:5432 (airflow / airflow)

-----------------------------------------------------------------------
4. THE TWO MINI-SERVERS (APIs)
-----------------------------------------------------------------------

The project presents two different ways of consuming data:

A. Flask Server (Port 8181):
- Role: Direct and fast reading of the CSV file via Pandas.
- Source: Lit /var/tmp/ventes.csv.
- Usage: Ideal for aggregated reports on the fly.

B. FastAPI Server (Port 8000):
- Role: Modern programmatic interface using an ORM.
- Source: SQLite database (generated by Airflow in /var/tmp/).
- Use: Detailed and structured sales consultation.

-----------------------------------------------------------------------
5. DATA MANAGEMENT
-----------------------------------------------------------------------

1. The "sales.csv" file at the root uses underscores (Store_A).
2. "make airflow-run" automatically copies it to /var/tmp/.
3. The /var/tmp folder is shared between the host and all containers.

-----------------------------------------------------------------------
6. DRIVING COMMANDS (MAKEFILE)
-----------------------------------------------------------------------

| Order | Action |
|------------------|-------------------------------------------------|
| make list | Help with available orders |
| make airflow-init| Setup complet (Image, DB, Admin, Perms)         |
| make airflow-run | Start the whole stack and copy the data |
| make fix-perms | Manually repair folder rights |
| makelogs | Displays logs in real time |
| make purge | TOTAL CLEANING (Deletes images and volumes) |
